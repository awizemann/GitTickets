## Description

ShabuBox ask #1, their highest priority. A policy option rendering attachment links with generic labels ("image 1", "attachment 2") instead of the user's filename, so "Tax Return 2024.png" stops becoming public link text in a world-readable issue. Sequenced AFTER P1 because both need Policies.swift.

## Plan

Base: release/v2.1.0 AFTER P1 (absolute-path redactor) has merged — both phases edit Policies.swift, and P1 owns it first. Then owns Sources/GitTickets/PublicAPI/Policies.swift (PrivacyPolicy only — leave P1's DiagnosticsRedactor work alone), Sources/GitTickets/Bodybuilder/IssueBodyBuilder.swift, and their tests.

WHY: IssueBodyBuilder.swift:100-103 renders `![\(safeName)](\(safeURL))` / `[\(safeName)](\(safeURL))`, so a user's filename becomes public link text even though the bytes sit behind an unguessable R2 URL. The dedicated screenshot path at :75 already does the right thing — `![screenshot](url)` with no filename. KEEP that behavior exactly as it is.

API (Alan chose OPT-IN so behavior is unchanged for existing adopters):
```
public enum AttachmentNameDisplay: Sendable, Hashable {
    case filename   // default — current behavior
    case generic    // "image 1" / "attachment 2"
}
// on PrivacyPolicy:
public var attachmentNames: AttachmentNameDisplay
public init(bannerText: String? = nil, requireExplicitConsent: Bool = true, attachmentNames: AttachmentNameDisplay = .filename)
```
SOURCE COMPATIBILITY IS A HARD REQUIREMENT: `PrivacyPolicy(bannerText:requireExplicitConsent:)` must keep compiling untouched, so the new parameter MUST be defaulted and MUST come last.

NUMBERING: use ONE shared 1-based index across the whole attachment list, with the noun chosen per item by isImage. So [png, pdf, jpg] renders "image 1", "attachment 2", "image 3". Do not restart numbering per kind — a stable index makes the Nth link in the body correspond to the Nth attachment, which matters when a maintainer is asking the user "what is in attachment 2?".

PLUMBING: IssueBodyBuilder.build(report:diagnostics:screenshotURL:attachments:) currently takes no policy. Add the setting as a defaulted trailing parameter so existing internal callers keep compiling, then thread it from the submitters. Check whether build() is internal or public before deciding what counts as a break, and report which callers you touched.

ACCEPTANCE (from ShabuBox): with the option on, NO user-supplied filename appears anywhere in the rendered body. Scope note to honor in the test's naming/comments: text the USER TYPED into their own description is theirs and still appears — this option governs SDK-injected attachment metadata only. Do not attempt to scrub the user's own prose.

VERIFY: tests for both modes; a test proving the screenshot line at :75 is unaffected; a test with a mixed image/non-image list proving the shared numbering; and a test asserting a filename containing markdown metacharacters cannot break out of the link text in EITHER mode (there is a memory note on markdown injection in issue bodies — read footguns/Footgun — Markdown Injection in GitHub Issue Body first, and one on multipart header injection via filename). swift build 0 warnings, swift test green. Then a fresh-eyes audit: is there ANY other path where a filename reaches the issue body or title?
