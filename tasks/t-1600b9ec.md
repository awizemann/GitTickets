## Description

The throwaway harnesses that established the macOS refresh finding should live in the repo so the next person can re-run them instead of rebuilding the investigation from scratch. They are dev tools, not shipped code — they must stay outside Sources/ so nothing reaches adopters.

Three of them: an iOS UIRefreshControl scan (proves .refreshable DOES work on iOS ScrollView), a macOS three-way control (ScrollView plain vs ScrollView refreshable vs List refreshable), and a macOS harness hosting the REAL SDK view.

## Plan

Land under Harnesses/ at the repo root, outside any declared SwiftPM target.

- Harnesses/README.md — what each proves, how to run, and the measured result
  so the finding is not lost if someone reads only the directory.
- Harnesses/RefreshAffordance/ — SwiftPM package with the two macOS executables
  (repro control + real-SDK), depending on the root package by path.
- The iOS one cannot be a SwiftPM simulator target; keep it as a source file
  plus a build-and-run script using swiftc + simctl.

Verify afterwards that `swift build` and `swift test` at the root are unaffected
by the nested package, and that .build directories under Harnesses are ignored.
