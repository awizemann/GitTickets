## Description

Once the current work is settled. A sweep of every public surface to confirm it is accurate and current, and to add release notes where missing.

Motivated by a run of surfaces that claimed things that were not true: the v2.1.0 handoff said v1.1.0 was never tagged when it is (backfilled 2026-07-25); GitTicketsMyIssuesView's header claimed the .refreshable gesture worked on macOS; MyIssuesPolicy.pollInterval promised a ⌘R shortcut nothing implemented; a prior handoff told Alan to test screenshots via a form affordance that does not exist. The pattern is documentation describing intent rather than measured behavior.

## Plan

Cover, and check each against actual behavior rather than against other docs:

- README, CHANGELOG, and everything under docs/.
- GitHub: releases and their notes, tags (do all announced versions exist and point where the changelog claims?), repo description, topics, issue and PR templates.
- Doc comments on public API — the pollInterval and header-comment cases show these drift silently.
- The wiki tier and design tier for stale claims.
- CHANGELOG structure: the [Unreleased] section currently sits at the BOTTOM of the file, below 1.0.0, where a reader will not find it. Move it to the top.
- Verify every version link reference resolves.

Where a claim cannot be verified, remove it rather than soften it — the v1.1.0 false toolchain claim is the precedent for why.
